# Station economy, scavenging, building

## Station economy (`scripts/world/`, `scenes/props/`)

The gas stop's tills, instanced into `game.tscn`'s `World`. Money is `PlayerData.add_money`/`spend_money` (statics, not an autoload — plain state, no per-frame behaviour) emitting `Signals.money_changed`; nothing writes `current_money` directly. `ItemData.price` is what the delivery truck pays for one unit.

`GasPump` (`scenes/props/gas_pump.tscn`) holds a tank over `GasPumpData` (`tank_size`, `wholesale_price` paid to the truck, `pump_price` charged to customers — the margin is the business, `flow_rate` L/s) — duplicated at `_ready` so two pumps never share a tank, exactly like `VehicleData.current_fuel`. Five areas: `RefuelArea` (HOLD, `interact`), `CanArea` (HOLD, `interact_tertiary` — `fill_can` pours into the first `FuelCanData` in the pack with room, row-major like the grid; the player's own stock, so free like the car), `ServiceArea` (`interact_secondary`, flips `selling`), `CarArea` (car layer — a parked vehicle), `ProximityArea` (reveals the gauge). The nozzle is only ADVERTISED while a car is actually parked, via `InteractiveArea.enabled`; the can offer likewise only while a can with room is carried AND the tank has stock — recomputed when the offer is NOTICED (`InteractiveArea.noticed`, which fires before the stage is judged; the old area-entry hook read `enabled` before the pump could look in the pack), on top-off, and on running the tank dry. `buy_stock(liters)` (truck) is all-or-nothing; `sell_gas(liters)` (customers) returns 0 while `selling` is off; refuelling the player's own car is free — it's their fuel — and moves `flow_rate * delta` per frame out of stock. The gauge is a `ProgressBar` in a `SubViewport` on a billboarded `Sprite3D`: a scaled quad cannot anchor its own fill once billboarding spins it to face the camera.

## Scavenging (`scripts/world/loot_container.gd`, `scripts/data/loot_*_data.gd`)

`LootContainer` INHERITS `StorageLocker` and adds two things. It stocks itself from a `LootTableData` the first time it is opened, never at `_ready` — so every crate on the map is identical until somebody actually looks inside, and nothing is decided before it matters (`searched` is what stops a second search re-rolling an infinite supply). `LootTableData` is a weighted bag of `LootEntryData` ({item, weight, count range}) plus a `draws` range for how many entries one container rolls; weights are RELATIVE, so adding an entry never means re-tuning the rest (though it does SHIFT every later roll in the deterministic headless traces). A rolled item with `has_own_state()` (the `ItemData` virtual for live per-instance state: a weapon's magazine, a fuel can's fill) is `duplicate()`d before it lands in the grid — the canonical `.tres` would share one live state between every crate on the map and the player's own copy — and at count > 1 it is added ONE FRESH DUPLICATE AT A TIME, because `Inventory.add` reuses a single resource across the entries it makes for non-stackables. A looted weapon arrives with `current_ammo` untouched at -1, i.e. unloaded until armed, when it fills from carried ammo like any other equip. Everything stateless is handed out shared, exactly like the tables always did. And it MARKS ITS OWN OFFER: `mark_searched()` sets `spent` on every `InteractiveArea` under it (found by TYPE, never by node name), which is what turns the feed-forward dot hollow — from `open()` for a fresh search and from `load_state` for a save that remembers one, since the flag lives on a node and the searched bit lives in the row. Their `SearchArea` is a POINT with `prompt_range = 1.8` — the 2.4m box it used to be, restated as the number it always really was (see UI.md).

THE LOOT BOXES are two flavors × three sizes (`scenes/props/cardboard_box_*.tscn` / `army_crate_*.tscn`, group `loot_container`, "Search" prompt): CARDBOARD (`data/world/cardboard_box.tres`) is trash and common parts — trinkets only, never guns or ammo; ARMY (`data/world/army_crate.tres`) is the four ammo types, grenades, the rarer parts (`machined_bearing`/`servo_motor`, UNCOMMON/RARE trinkets) and every ranged weapon at jackpot weights (0.2-0.8 vs ammo's 4.0). SIZE sets the grid (`data/storage/box_{small,medium,large}_layout.tres`: 3x3 / 4x4 / 6x5) and `LootContainer.extra_draws` on the scene (+0/+1/+3) tops up the shared table's `draws` range so a big box is fuller, not just roomier. Meshes come out of `_not_exported/containers/` via `_tools/asset_extractor/extract_containers.gd` into `assets/meshes/props/containers/` sharing one material (an unwired `loot_box_wood_small` rode along) — and that `containers_material.tres` is really the whole KayKit RESOURCE BITS kit's material (one atlas), shared by everything later pulled from the same pack (`extract_resource_bits.gd` → `assets/meshes/props/resource_bits/`, the jerrycan first), so a rename to `resource_bits_material` is an in-editor-only cleanup; collision boxes in the scenes are the measured mesh AABBs, and every mesh sits origin-at-base. `game.tscn`'s `World/Crates` places all six (two spots pair a big box with a small companion). The old placeholder (`scenes/props/loot_container.tscn` + `crate_layout.tres` + `desert_scavenge.tres`) is superseded but kept: `loot_probe` still exercises the generic table/mask directly, and `boxes_shot` (windowed, `world/`) renders the six props for a look check. That closes the money loop: scavenge → sell to the trucker → buy pump stock → sell fuel. Most trinkets carry NO icon yet and the grid widget draws a placeholder for that, so art can land later without touching anything — the COG is the first with real art: `TrinketData` grew an optional `mesh` (kit-pulled parts carry one; `data/items/trinkets` is in the icon rig's SOURCE_DIRS, and only mesh-carrying trinkets render, the rest skip), its model extracted from the Resource Bits kit like the jerrycan, and it sits in BOTH loot tables (a common mechanical part: cardboard weight 3.0, army 2.0) as well as flying burning out of every car explosion.

`StorageLocker` (`scenes/props/storage_locker.tscn`) is the player's own stash: an `Inventory` over an exported `StorageData` mask, so a bigger locker is DRAWN as ASCII like a backpack. `open()` emits `Signals.container_opened`, the identical call `Vehicle.open_trunk()` makes, so `BackpackScreen` needed no change at all. It USED to be a vending machine the truck bought out (`VendingMachineData` tiers, `sell_all()`); selling moved onto the truck's own counter, so the machine kept only the box.

## Building (`scripts/world/build_grid.gd`, `scripts/components/player/player_build.gd`, `scripts/data/buildable_data.gd`)

The player PLACES structures at runtime on a 1.5m grid — half a terrain cell, so the two align every second cell. `BuildGrid` (node in game.tscn's `World`, registered as `Globals.build_grid`) is the model: `cell_of`/`world_of` convert (a footprint's node sits on its CENTRE, so a 2x1 straddles both cells rather than perching on one), `rotated_size` swaps the footprint on quarter turns only, and `can_place` refuses FOUR ways — a cell already in `occupancy`, ground that is not the FLAT map floor (`level_ground` rays down and demands |y| < 0.25, which rules out terraces, cliffs and the void), anything solid standing in the way (`obstructed`, a box of air over the footprint; it starts ABOVE the floor deliberately, because the ground carries the walls layer too and a box touching it reads as a wall), and MARKED GROUND (`marked_ground`, 2026-08-13): props with no collider to be found by — a crop spot is a bare Marker3D — already announce themselves through the `no_grass` group for the grass clearance, and the same declaration claims their cell against building, because the obstruction box cannot see them and a barrel got set down on a planted crop. A dying claim is no claim: the whole ANCESTRY is checked for `is_queued_for_deletion`, since demolishing a plot queues the ROOT while its spot lingers in the group until the free lands at frame's end. `BuildableData` (`data/buildables/`) is what can be built: scene, footprint in cells, price. PLACED BUILDINGS ARE RUNTIME CHILDREN, so `SaveManager`'s authored-nodes-only rule cannot see them — the grid serialises them itself and NESTS each one's own `save_state()` in the row (the barrel's fuel, a plot's crops), exactly the trick `CropPlot` uses for its crops; anything placeable therefore persists for free if its root already saves. `PlayerBuild` (component on player.tscn) is the input half: B opens the catalogue through `InteractionMenu` and B again leaves, a ghost of the real scene follows the cursor's cell tinted green/red (`BuildGrid.make_ghost`, shared with the carry: EVERY script stripped before the tree sees it, colliders zeroed, process disabled — disabling alone is not enough, because `_ready` still runs on add_child and the self-registering pieces gave a ghost a live "Pick up"/"Plant" offer and a CoolArea shelter of its own; a preview is MESHES, made inert by construction), T rotates, and the click places and spends — it claims the attack button via `holds_attack()` exactly as PlayerThrow and PlayerConsume do, so building never fires the gun. The ghost STAYS up after a placement, so a row of plots is one pick and several clicks. `InteractionMenu` rows grew an optional `argument` (passed to the callback in place of the usual null) so one `start` callback can serve a whole catalogue. First buildables: a one-spot `crop_plot_single.tscn` (the farming plot, which is just a CropPlot whose own save rows ride along) and the fuel barrel. THE GRID ADOPTS AUTHORED CHILDREN (2026-08-12): a buildable the designer drags into the editor as a CHILD of BuildGrid (game.tscn's HomeBase barrel moved there) is registered at `_ready` into the same `occupancy`/`placements` books a runtime placement gets — matched to its catalogue entry by `scene_file_path`, snapped to the cell it nearly stands on — and REMOVED from the `persistent` group, because the grid's ledger saves it now and a row in both would spawn twins on load (`FuelBarrel._ready` skips the group under a BuildGrid parent for the same reason, belt and braces). This is what makes PICKING A BARREL UP save-coherent: `forget(node)` is demolition's bookkeeping half without the free — the node lives on, carried (or lingering as its own fading chill, Desert.md) — and wherever it is set down, `place()` records it again; there is exactly ONE ledger whichever path a barrel took into the world. `demolish` now routes through `forget` too. Probes: `build_probe` (17: grid maths, rotation, all three refusals, demolition, the nested save round trip) + `carry_probe` (world/, the adoption and pickup half) + `build_shot` (windowed; note it must `set_process(false)` on the component or its per-frame cursor read clobbers the staged cell). A CARRIED BARREL DRAWS THE POCKET IT WOULD VENT (2026-08-13): while the cursor's cell would actually take it, `RangeRing` (`scripts/vfx/range_ring.gd` — an ImmediateMesh disc under a rim, built in WORLD space with `top_level` the way `VisionConeVisual` is) circles the ghost in COLD BLUE, deliberately not the ghost's green, because the tint answers "may it stand here" and the ring answers "how far would it cool" — two questions in one colour read as one. The radius is read off THE GHOST'S OWN `CoolArea` sphere (make_ghost strips scripts, not NODES, so the preview still carries the shape), which keeps a second copy of the number from drifting off the scene and makes the circle exactly what `SandField` will paint as the chill spot. A refused cell passes radius 0, which is the ring's own hide, so the caller keeps no visibility rules. Two traps: Godot 4 dropped `TRIANGLE_FAN`, so the disc is wound by hand as the vision cone's fan is; and a rim-carries-the-reading fill (0.06 alpha under a 0.9 rim) is what stops a 7m circle turning the sand milky and losing its own edge. `carry_shot` (windowed, world/) toggle-diffs the ring out of the same frame, because `visible == true` and a surface count prove nothing about pixels.
