# Autoloads

- `Settings` (`scripts/managers/settings.gd`) — player settings over a `user://settings.cfg` ConfigFile (`[interface]` time_format/unit_system, `[display]` resolution/fullscreen): `time_format` (`Enums.TimeFormat` 24h/12h), `unit_system` (`Enums.UnitSystem` metric/imperial), `resolution` (offered from the `RESOLUTIONS` const, `get_available_resolutions()` trims what won't fit the monitor but never drops the saved choice), `fullscreen` (F11's `FullscreenToggle` flips this, so key and menu can't disagree). Assigning any of them is the whole API — the setters apply to the window, save to disk, and emit `Signals.settings_changed`; there's no apply button and no explicit save call. UI must never hardcode a clock style or unit: `format_time(hour, minute)` and `format_speed(m/s)` are the display path (HUD clock and vehicle speedo use them, and both re-render on `settings_changed`). Defaults: 24h, metric, the project's own window size, windowed. Edited from the `SettingsScreen` (`scripts/ui/menus/settings_screen.gd`, the `Overlay/Settings` panel in game.tscn — `process_mode = ALWAYS` so it runs while the tree is paused): `pause_game` (ESC) opens it and pauses, ESC/Cancel closes and resumes. The rows are BUILT from the script's `Row` enum + `row_data()` table — one `scenes/ui/settings/settings_row_list.tscn` per entry into `%ListContainer` — so a new setting is an arm in `row_data()` (title, the real values its arrows cycle, their labels, and the autoload's current value), an enum entry, and a line in `apply()`; the scene never changes. Picks are STAGED in `pending` (Row → real value, not index) and only reach the autoload on Apply, which is what makes Cancel free and lets the Apply button disable itself while nothing differs; Apply writes resolution BEFORE fullscreen (a resize is skipped while fullscreen, so the other order resizes twice on the way out), and picking Fullscreen greys the resolution row. `SettingsRowList` (`scripts/ui/settings/settings_row_list.gd`) is a dumb cycler — title, value label, two arrows that WRAP at both ends — it knows nothing about what the options mean and just emits `value_changed(index)`. The panel hides itself in `_ready` rather than trusting the scene's `visible` flag: it's designed IN the editor, and saving it while it's on screen would otherwise ship it visible.

- `SaveManager` (`scripts/managers/save_manager.gd`) — one JSON save + rolling backup (`user://save.json`/`.bak`, versioned; `save_path`/`backup_path` are VARS so probes point them at scratch files and can never eat the real save). Scene-authored members of the `persistent` group (owner != null — runtime spawns like traffic have none) contribute `save_state()`/`load_state()` Dictionaries keyed by scene-relative path: PlayerPersistence (position/health/energy/pack/quick bar/holster), StorageLocker (+LootContainer's `searched` — an unsearched crate saves nothing and stays a fresh roll), Vehicle (spot/yaw/tank/hull/trunk), GasPump, DeliveryService (`last_delivery` only — a mid-visit truck is NOT saved; the day counts as served). Items serialize as resource paths + counts + exact grid origins (+ `current_ammo` for weapons, `current_fuel` for fuel cans; anything `has_own_state()` is re-duplicated on load); RUNTIME COPIES have no `resource_path`, so identity falls back to the item's unique NAME against a one-time walk of `data/items` (`item_path`). LOADING reloads the scene and applies on top, gated by a FACT barrier, not frame counts: a live `current_scene` CONTAINING an armed player — the swap lands at frame's end (current_scene is briefly null, and the OLD player is still valid to a lone player check), and `Character.apply_data` defers the loadout one more frame; frame-counting lost this race twice. Death loads the last save (`DeathScreen.respawn`, fresh-scene fallback without one); SLEEPING IS THE ONLY WAY TO SAVE — the bedroll's second "Save game" offer is gone (it sat on the same point as the sleep, two dots for one bed), so a day cannot be banked without spending it; enemies deliberately reset every load. Probe: `save_probe` (12 checks incl. death rollback + backup rotation).

- `Calendar` (`scripts/managers/calendar.gd`) — game clock over a `TimeData` resource (`scripts/data/time_data.gd`: 28-day months, cascading carry, starts 08:00 1 Jan 1989): one game minute per real second (`HOUR_DURATION = 60` → 24-minute day), emits `Signals.calendar_updated(time_data)` each minute (first emit deferred past autoload `_ready`), `set_time(hour, minute)` never rewinds — an earlier hour rolls to the next day. ANY HOUR GATE ASKS `past_hour(hour, minute)`, NEVER `time_data.hour == x`: the clock jumps whole hours at a time (a debug scrub, a sleep, a loaded save, and `set_time` itself emits only once), so an exact test can miss its instant and the thing waiting on it never fires — that is what left the delivery truck parked at its bay past closing time (see [[Traffic]]). The predicate compares MINUTES-of-day, same as `set_time`'s own rollover test, and reads as "at or past", which makes it same-day only: a span that crosses midnight needs its own test, not this one. `get_day_fraction()` is the continuous 0-1 midnight→midnight time (interpolates the in-flight minute from the timer) read by `DayNightCycle` (`scripts/components/day_night_cycle.gd`, node in game.tscn's `World`): every frame it samples scene-authored Curve/Gradient resources and writes sun pitch/energy/color, ambient color/energy, and the compositor vignette's color AND radius. The seven graphs are keyed on the day PHASE, not the clock — `day_phase()` scales the two night stretches and the daylight one independently so the horizon crossings ALWAYS land on 0.25/0.75, which makes `SUNRISE_HOUR`/`SUNSET_HOUR` (6.0/18.0, an exact identity at those values) the one place to move daylight: every key of every graph slides with them, e.g. 5:00/20:30 stretches the high-sun plateau from 8-16h to 7:35-17:55 on its own. The plateau reproduces the original hand-tuned afternoon exactly; night is a dim blue "moon" at 40° elevation (the light never goes below the horizon — the crossings are the elevation curve's minima, not sign changes). DARKNESS COSTS SIGHT: the vignette's colour is only its tint, `vignette_radius` is its REACH — 1.0 parks the dark ring out at the corners (the value authored on the effect, so daylight is unchanged) and 0.75 after dark drags it in over the playfield, taking the top/bottom screen edges from 32% to 77% darkened while the centre stays clear. It is keyed on the same phase offsets as `vignette_color`, so reach and tint move together. The effect's `softness` (0.8) stays authored and uncurved on purpose: it is the WIDTH of the falloff band, so a curve on it would sharpen the ring into an iris rather than show more or less world. Exported node refs (sun, world_environment); unwired (the gym) = inert. HUD clock+date panel (`CalendarInfoUI`, top-right) listens to the same signal.
