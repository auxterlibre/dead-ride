# State machine and data resources

## State machine (`scripts/state_machine/`)

The generic base (`state_machine.gd`, `state_interface.gd`): a code-driven machine created by its owner at runtime; states are plain non-node objects registered via `add_state()`. First consumer: `EnemyAI` (states in `scripts/components/enemy/states/`).

## Data-driven resources (`scripts/data/`, `data/`)

- `CharacterData` (Resource): health, speed, vision/detection ranges, `body_path`, `ai_script`, `weapon_inventory: Array[WeaponData]`. Instances in `data/enemies/`.

- `WeaponData` (Resource): type (`Enums.WeaponType`: MELEE_1H/MELEE_2H/RANGED_1H/RANGED_2H), stat knobs, `model: PackedScene`. Instances in `data/items/weapons/`. Stats are player-facing 0-100 int knobs remapped to real units via `*_SPAN` consts — gameplay code reads the `*_value` getters, never the knobs; counts and calibration (`max_ammo`, `projectiles_per_shot`, `aim_yaw_offset`, `cock_time`) stay literal. `Enums.FireMode.MANUAL` (the sniper rifle) must CYCLE THE ACTION between shots: `fire_shot` arms `needs_cocking` for `cock_time` seconds and `can_fire` gates on it (both AIs and the player go through `can_fire`, so nobody needed teaching); the eject sound (`AudioEject` node on the weapon scene, optional — `play_eject` no-ops without one) fires at `EJECT_SHARE` of the cycle, and the BOLT WORK IS VISIBLE: once the shot clip's recoil frames finish, the reload clip plays time-scaled into what remains of the cock (the same clip-fitting trick `reload()` uses on `reload_time`). Cancellation goes through `cancel_cock()` — holster MUST call it or the next `_process` reads `cock_time` off a null weapon. Emptying the magazine skips the cock (nothing to chamber) and a reload absorbs a pending one — the bolt is worked as part of both; equip clears it (hand state, not weapon state). `is_ranged` is derived from the enum name prefix — keep the `MELEE_`/`RANGED_` naming convention if adding types.

- `VehicleData` (Resource): health, mass, engine power, speed, brake force, `handling`/`drift`/`engine_tone` — ALL player-facing 0-100 knobs remapped via `*_SPAN` consts (`*_value` getters); the three dials additionally fan out to several physics internals each in `Vehicle.apply_data()`. 50 on every dial reproduces the original hand-tuned car. Instances in `data/vehicles/`.

- `ItemData` (Resource, base of `WeaponData`/`BackpackData`): `name`, `weight`, `size` (grid footprint, RECTANGLES only), `icon`, `rarity`, and `model: PackedScene` — EVERY item's 3D body lives here, not on subclasses. It is a SCENE, never a bare Mesh, so poses are authored in the editor (the laid-down screwdriver bakes the 90° that `icon_rig.subject_for` used to special-case; mesh-only kit pulls get a one-node wrapper scene from `_tools/asset_extractor/make_item_models.gd`). The hoist is what deleted `subject_for`'s `get("model")`/`get("mesh")` duck-typing — before it, four data classes declared the same thing under two names and two types. THREE SCENE PROPERTIES NOW COEXIST and they are not interchangeable: `model` (display: icons, future world drops), `get_held_scene()` (posed for the hand), and the grenade's `thrown_scene` (a live RigidBody — renamed from `model` precisely so hoisting could not silently hand the icon renderer a physics body by accident; the grenade sets BOTH to the same scene today, and that is a choice, not a requirement). `BackpackData.mesh`+`skin` stay a Mesh/Skin pair — that one is rig-bound clothing `SkinManager` assigns onto a slot, not a free-standing model. Two virtuals feed the tooltip so the UI never switches on type — `get_category_label()` ("Assault rifle", from `WeaponData.weapon_class`) and `get_stat_lines()` ([label, value] pairs; weapons return the player-facing 0-100 knobs plus magazine/ammo type). `Enums.Rarity` has exactly FOUR arms because `Palette` (`scripts/core/palette.gd`) defines four rarity colours — `get_rarity_color()` maps them, and both the tooltip label and the grid backing read it, so adding a rarity means adding a Palette colour first.

- `StorageData` (Resource, `data/items/storage/`): a container's grid, authored as an ASCII MASK in one `@export_multiline` string — `.`/space = usable, anything else locked — so a new backpack is DRAWN, not counted (`XXXXXX / X....X / ...` is the hiker pack's octagon, 6x6 with 20 usable cells). Parsed once into a cached size + open-cell set. `BackpackData.storage` and `VehicleData.storage` both point at one; that sharing is the whole of "vehicle trunks work like backpacks". THE INSPECTOR DRAWS IT AS CHECKBOXES now (2026-08-12): `addons/storage_painter/` replaces the layout's multiline editor with width/height spinners and a grid of toggles — the STRING stays the stored format (every authored .tres valid, diffs readable), the widget just writes it through `emit_changed`, so undo works. Growing opens the new ground; shrinking truncates visibly, boxes falling off the edge. The string<->grid conversion is STATIC on `storage_grid_property.gd` precisely so `storage_painter_probe` (inventory/, 9 checks) can hold it to account headless — round trips, spaces composing back as `x`, ragged rows widening to the longest, the empty string reading 1x1 — while the widget itself stays editor chrome.

- `AttackData` / `InputData` — plain data carriers.
